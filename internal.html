02
Authentication

鉴权：API Key + 签名 标准静态密钥 · 无 Token 生命周期 💡 相对上游变更

途鸽 V2.0 用「换取 24h Token + 过期刷新」的动态令牌；XPIN 改为 静态 appKey + appSecret 请求签名， 取消 /oauth/token、/oauth/refreshToken 两个接口，下游无需管理 token 生命周期，接入更简单稳定。

🔑 请求鉴权头（每个请求携带）

Header说明
X-Api-KeyappKey，标识调用方
X-TimestampUTC+0，服务端校验 ±5 分钟窗口
X-Nonce一次性随机串，窗口内去重防重放
X-Sign请求签名（见右）
Content-Typeapplication/json;charset=UTF-8

🔏 签名算法 · HMAC-SHA256

1. 取 body 参数 + X-Timestamp + X-Nonce（排除 X-Sign / 空值）
2. 参数名 ASCII 升序，嵌套展开 父.子
3. 拼 key1value1key2value2… 无分隔符
4. X-Sign = HMAC-SHA256(appSecret, 拼接串) → 64 位 hex 小写
兼容 signMode=MD5_LEGACY 对齐途鸽历史对接 错误：2002 Key 无效 · 2003 签名失败 · 2004 过期/重放

05
Conventions & Security

通用约定与安全

📐 请求 / 响应约定

传输HTTPS · 统一 POST · UTF-8
鉴权API Key：X-Api-Key + X-Sign（见 §鉴权）
时间UTC+0 · yyyy-MM-dd'T'HH:mm:ss'Z'
公共响应code · msg · subCode · subMsg · data
分页pageNum≥1 · pageSize≤100 · total + list
成功码0000

🔐 安全机制

API Key静态 appKey/appSecret，无过期，无刷新
请求签名HMAC-SHA256 + nonce + timestamp ±5min 窗口
幂等(appKey, idempotencyKey) 缓存原响应 ≥24h
Webhook 签名同算法，密钥为账户 appSecret
兼容模式signMode=MD5_LEGACY 兼容途鸽历史对接
限流超 QPS 返回 0429，阈值内正常

🚦 错误码归一（平台职责）

1003 参数校验2002 Key 无效2003 签名失败2004 过期/重放 0429 限流4001 产品不存在4010 余额不足 5044 开卡失败6002 profile 不存在 供应商码 → XPIN 统一码，原码透传 subCode

Integration Flow

集成主流程 推荐接入顺序

STEP 1

同步目录

products/list 拉取可售套餐，按 lastModifiedTime 增量入库。

STEP 2

创建订单

order/create 携 idempotencyKey + API Key 签名，同步拿到 orderNo。

STEP 3

接收回调

Webhook eventType=1 推送 qrCode / iccid，按 orderNo 幂等处理。

STEP 4

交付用户

由 qrCode 生成 eSIM 二维码 / iOS 一键安装链接交付。

STEP 5

用量与续期

order/usage 查流量 · iccid/profile 查安装 · order/renew 续订。
