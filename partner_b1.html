Integration

Integration Plan & Flow Live in five steps, supported throughout

STEP 1 · APPLY

Get credentials

XPIN issues appKey / appSecret (one set each for sandbox & production); report your callback URL and egress IP.

STEP 2 · AUTH

API Key signing

Send appKey and a signature in the headers — static keys, no token exchange, configure once and use long-term.

STEP 3 · SYNC

Pull plans

Call /products/list to sync sellable plans, then price, organize and present them on your platform.

STEP 4 · ORDER

Create order

After payment call /order/create with a unique idempotencyKey; the order number returns synchronously.

STEP 5 · DELIVER

Receive install info

After provisioning the platform pushes install info via callback; generate the eSIM to deliver, then usage / renewal are queryable anytime.

Security & Reliability

Security & Reliability

🔐

API Key + Signature

Static key + HMAC request signature, with a timestamp window and nonce to prevent tampering and replay.

🛡

Idempotent Safety

Order APIs use idempotencyKey so retries never double-provision or overcharge on network errors.

🔔

Reliable Callbacks

Provisioning results are pushed asynchronously and retried until your system confirms, with an IP allowlist to keep the source trusted.

🧱

Data Isolation

Each account can only query and operate its own orders and cards; accounts cannot see each other's data.

🌐

Sandbox

Independent sandbox and test plans; integration incurs no real cost — switch to production once verified.

🤝

Integration Support

Docs, sample code and technical support to help you go live smoothly.
