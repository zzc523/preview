1. 概述#

通过本文档的两个接口，你可以拉取发布给你的在售套餐，套餐对象采用 DataPlan 结构。

项 说明
接口 /openapi/v1/products/list（商品列表）、/openapi/v1/products/detail（商品详情），见 §4
购买方式 每个套餐带 link，指向该套餐的购买页面，消费者在那里完成购买

2. 基础约定#

项 值
Base URL（联调环境） https://sandboxapi.xpin.network
Base URL（生产环境） https://openapi.xpin.network
协议 全部 POST，Content-Type: application/json
字符集 UTF-8
成功判定 看响应体的 code 字段，不看 HTTP 状态码
凭证 平台发放的 app_key / app_secret（需要从平台方获取）。联调凭证只在联调环境有效

平台的业务应答一律是 HTTP 200，响应体统一为：

字段 类型 说明
data object 业务数据。失败时为 {}
code number 业务码。200 才是成功
msg string 成功为 ok；失败为错误码或字段级提示
t number 服务端毫秒时间戳。⚠️ 个别服务端异常响应（406）不带这个字段，不要当作必有字段解析

🔴 判定是两步，不是一步。 路径前缀写错、用了 http://、连接中途出错时，请求根本没进到 业务层：你拿到的是一个真实的 HTTP 状态码，响应体可能不是 JSON。

断言一定要写 body.code === 200。写 res.status === 200 会把所有业务失败都当成功。

HTTP 80 端口的请求会 301 跳转到 HTTPS，且 301 不保留 POST body——直接用 https://。

3. 认证与签名#

每个请求带四个头：

请求头 说明
x-api-key 你的 app_key
x-timestamp 毫秒时间戳（13 位），与服务器时钟偏差需 ≤ 5 分钟（双向）
x-nonce 随机串，匹配 ^[A-Za-z0-9._:-]{8,128}$，同一商户同一 nonce 在 10 分钟内只能用一次（见 3.2）
x-sign HMAC-SHA256 十六进制小写，见 3.1

3.1 签名算法 XPIN-KV1#

签的是解析后的数据，不是报文字节 —— 所以你的 body 用任何 JSON 库、任何键序、任何缩进 发出都行，也不要求你能控制 HTTP 客户端实际发出的字节。被签的对象固定七个字段：

把它按下面四条规则拼成基串，再 hex(HMAC_SHA256(app_secret, base))。

R1 拍平 —— 递归展开成「路径 → 标量」的列表：

  • 嵌套对象：路径段用 . 连接。{"data":{"code":"X"}} → 路径 data.code
  • 数组：下标就是一段。{"tags":["a","b"]} → tags.0、tags.1
  • 空对象落一条 路径 → o:，空数组落一条 路径 → a:。不留痕的话 {"a":{}} 与 {} 会拼出同一个基串
  • 键名必须匹配 ^[A-Za-z][A-Za-z0-9_]*$。不匹配就拒绝，不要尝试转义

R2 值编码（带类型标记）：

值 编码
字符串 s: + 原文（UTF-8，不转义任何字符）
整数 i: + 十进制，无前导零，-0 写作 0
布尔 b:true / b:false
null n:

数值必须是绝对值 ≤ 2⁵³−1 的整数（2 与 2.0 都按整数处理）。小数、超范围整数、 NaN、Infinity 一律拒绝，不要尝试编码。本渠道的请求体只有 pageNo、pageSize、 productCode 三个字段，正常使用碰不到这条。另有两条结构上限：嵌套深度 8 层、叶子总数 512， 超出分别是 CANONICAL_TOO_DEEP 与 CANONICAL_TOO_LARGE（都是 400）。

R3 每一项的字面量（长度前缀）：

⚠️ 长度算的是编码值整体的字节数，包含 s: / i: 这两个字符的类型标记。 "ak_demo" 编码成 s:ak_demo，长度是 9 不是 7 —— 这是最常见的一处实现偏差。

R4 排序与连接 —— 按完整路径的 UTF-8 字节序升序排序，用 & 连接。

3.2 nonce#

⚠️ x-nonce 请用真随机值，不要用时间戳、也不要用 body 的摘要。一旦 nonce 取成与 timestamp 相同的值，客户端把这两个实参传反将无法被签名发现。

去重范围与记忆期：按「环境 + 商户 + nonce」去重，记忆期 10 分钟。随机 nonce 天然满足这条约束， 无需自己维护池。

3.3 认证检查顺序#

多个条件同时不满足时，你只会看到最先命中的那一个：

第 8 步刻意与 SIGNATURE_INVALID 分开：它说的是"这份载荷里有一个签不了的值"， 不是"你的密钥不对"。看到 CANONICAL_* 请查载荷，不要查密钥。

配额：/products/list 与 /products/detail 合计每秒最多 qpsLimit 次，由平台为你的账号配置。超限返回 429 QPS_LIMITED，退避重试即可。 全量同步目录时请串行翻页，不要并发打满配额。

两条由此推出、对排障很有用的性质：

  • nonce 只在请求"本可成功"时才被消耗（第 11 步在最后）。所以错签名重试永远回 SIGNATURE_INVALID，不会被自己的重试污染成 NONCE_REPLAYED。
  • 参数校验在鉴权之前。缺必填字段时你拿到的是 400 xxx required，不是 401。

5. 套餐对象 DataPlan#

字段名、类型、枚举均与 eSIMDB Provider API v1.0.2 的 DataPlan 一致，五个必填字段 （validity、dataCap、dataUnit、prices、coverages）在每个套餐对象上都有。

5.1 字段#

字段 类型 何时出现 DataPlan 规格 说明
planName string 总是 可选 套餐名，超过 100 个字符截断
validity integer 总是 必填 套餐天数
dataCap integer 总是 必填 高速流量额度；日包是每天的额度。见 §5.2
dataUnit string 总是 必填 MB 或 GB
dataCapPer string 仅日包 可选 恒为 day。总量包不输出，即"额度不按周期重置"
reducedSpeed integer 仅超额后降速的套餐 可选 用完高速额度后的限速，单位 kbps。不输出表示用完即断网
prices object 总是 必填 售价。键是 ISO 4217 币种，值是 JSON 数字（不是字符串）。当前只有 USD
link string 配置了购买页时 可选 购买平台上该套餐的页面地址。已做 URL 编码，原样使用，不要解析或拼接
capacityInfo string 有说明时 可选 流量规则说明，如 50GB high-speed data, stop when used up
coverages array 总是 必填 覆盖国家，ISO 3166-1 alpha-2。两种形态见 §5.2
subscription boolean 总是 可选 恒为 false：平台没有自动续费的套餐
promoEnabled boolean 总是 可选 恒为 false：平台不支持优惠码。DataPlan 中该字段缺省为 true，所以显式给出

5.2 取值规则#

流量额度：dataCap / dataUnit / dataCapPer#

套餐 dataCap dataUnit dataCapPer 例
总量包 整个有效期内的高速流量 恒为 MB 不输出 50GB 套餐 → 51200 / MB
日包 每天的高速流量 GB 或 MB day 每天 2GB → 2 / GB / day
  • 总量包按 MB 给出、不换算成 GB：dataCap 只能是整数，1536MB 换成 GB 是 1.5，取整就会凭空多报或少报半个 G。
  • dataCap 不会是 0：DataPlan 中 0 表示"真正不限量"，当前目录里没有这样的套餐。宣传为 Unlimited 的日包是"每天 N GB 高速、超出后降速"，按上表输出，降速值在 reducedSpeed。

降速：reducedSpeed#

  • 日包：用完当天的高速额度后降到这个速率，单位 kbps（例如 512），第二天恢复高速。
  • 总量包：用完即断网，不输出这个字段。DataPlan 中它的缺省值 null 即"用完即断网"。

覆盖国家：coverages#

DataPlan 允许两种形态，二者择一；两种都会返回，请两种都支持：

形态 何时使用 例
纯国家码数组 多国套餐恒为此形态；单国套餐拿不到可靠的运营商信息时也用它 ["CA", "MX", "US"]
对象数组 单国套餐，且能确认该国的运营商时 [{"code": "ID", "networks": [{"name": "Telkomsel"}, {"name": "XL"}]}]

对象形态里的 networks 只有 name，不含 types（3G/4G/5G）：平台没有网络制式这项数据， 不会编一个。

其它字段#

  • prices：售价，值是 JSON 数字。当前所有套餐只有 USD 一个币种。
  • link：其中的商品码部分已做 URL 编码（如 / 编码为 %2F），请原样作为跳转地址使用。没有配置购买页的套餐不输出 link，平台不会给出一个打不开的链接。
  • planName：套餐的对外名称，超过 100 个字符截断。

5.3 不输出的字段#

DataPlan 的其余字段平台不输出，按各字段的缺省值理解：

字段 缺省值 对本渠道套餐意味着
hasAds / payAsYouGo / newUserOnly false 无广告、不按量计费、不限新用户购买
maxSpeed null 高速额度内默认不限速
canTopUp / eKYC / tethering null 未知：平台没有这项数据
telephony / internetBreakouts / subscriptionPeriod null / 无 未知：平台没有这项数据
priceInfo / validityInfo / additionalInfo 无 没有额外说明
activationInfo — DataPlan 中已废弃，不输出

5.4 示例#

总量包：90 天共 50GB，用完即断网，所以没有 dataCapPer 与 reducedSpeed。

日包：5 天，每天 2GB 高速，超出后降到 512kbps。

code msg 含义 你该做什么
200 ok 成功 —

404 PRODUCT_NOT_FOUND 商品不存在或不属于你 核对 productCode
404 — 路径拼写错误（前缀对、路径名错）。msg 不是稳定错误码 核对路径名

跨租户隔离：查不到与"不属于你"返回同一个 404，平台不会告诉你"这个商品存在但不是你的"。

6.1 非 200 的响应怎么处理#

有一类响应根本没有进到业务层，它们带真实的 HTTP 状态码，响应体可能不是 JSON：

你会看到 通常是因为
301 + 非 JSON 用了 http://。301 不保留 POST body，直接用 https://
404 + 非 JSON 路径前缀写错（正确前缀是 /openapi/v1）
429 请求频率异常 —— 退避重试，并检查客户端有没有重试风暴或死循环
